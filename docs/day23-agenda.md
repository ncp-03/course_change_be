# 23일 회의 안건

## 1. 오늘까지 된 것

- 백엔드 뼈대 + Swagger UI, 공통 에러 형식
- MySQL 스키마 확정 (테이블 11개, 한 학기 단순화) + ERD 이미지: `docs/erd.png`
- API 3종 구현·테스트: 강의 조회(목록·검색·상세·필터), 데모 로그인(`X-Student-Id`), 내 수강 목록
- GitHub Actions: push마다 테스트와 jar 실행 확인 자동 실행
- API 목록 문서: `docs/api.md`

## 2. 먼저 확정할 것 (구현 전에 막히는 것)

| # | 안건 | 현재 상태 | 제안 |
|---|---|---|---|
| 1 | **교환 대상 범위** | 노션 '기능 확정'은 강의명이 달라도 교환 가능(분반까지 같은 강의만 불가), DB 조사 초안은 '같은 과목의 다른 분반끼리만'으로 서로 다름. 현재 스키마와 구현은 다른 과목 허용 기준 | 다른 과목 허용으로 확정하고 DB 초안 문서를 고친다 |
| 2 | **5분 타이머 시작 시점** | 회의록에 '세션 열릴 때부터'와 '첫 동의부터'가 같이 있음. 현재 스키마는 세션 생성 시 `expires_at`을 정함 | 세션이 열릴 때부터 5분(재확인 유예시간 포함)으로 단순화. 첫 동의 기준으로 바꾸면 아무도 동의하지 않은 세션의 최대 대기시간을 따로 정해야 함 |
| 3 | **거절 감점** | 1~2점으로만 정해짐 | 1점 또는 2점 중 하나로 확정 (사유별 차등을 둘지) |
| 4 | **무응답 감점의 귀책 기준** | 만료 시 5점. 둘 다 동의 안 했을 때 둘 다 감점인지, 안 누른 쪽만인지 불명확 | 동의 안 한 사람에게만 5점 |
| 5 | **이용 제한 기준·기간** | '경고 → 계속되면 매칭 막음'만 있음 | 누적 감점 몇 점에 몇 시간 제한할지 숫자 정하기 |
| 6 | **재매칭 유예시간** | '유예 후 다시 매칭'만 정해짐 | 시간 값 확정 (예: 10분) |
| 7 | **재매칭 때 대기 시작 시각 유지 여부** | 미정. 유지하면 기다린 시간 가산점이 이어짐 | 유지 (실패가 본인 잘못이 아닐 때) |
| 8 | **우선순위 점수 공식** | 요소만 정해짐: 학년, 기다린 시간, 현재 학점, 희망 순위, 감점 | 가중치·동점 처리 기준 숫자로 확정 |
| 9 | **학생당 동시 교환 요청 수** | DB 초안은 1개, 현재 스키마는 보유 강의마다 1개씩 가능 | 보유 강의마다 가능으로 확정. 이 경우 최종 시간표·학점 검사를 매칭 때마다 다시 해야 함 |
| 10 | **알림 방식** | NCP Simple & Easy Notification Service를 쓰기로 했으나 웹 푸시로 되는지 미확인 | 담당자가 가능 여부 확인. 안 되면 폴링으로 시작 |
| 11 | **감점 누적 범위** | 학기를 넘겨 이월할지 미정 | 데모는 한 학기라 이월 없음으로 단순화 |
